022 景深环形卡片与流体渐变

大多数卡片轮播只是把卡片排成一行，然后横向平移。景深环形卡片不一样：它把整排卡片卷成一个环，再让摄像机站在环内或环外。

看起来像两种完全不同的效果，其实只是同一个环、同一台摄像机、同一套材质在两个位置上的结果。空间感不是靠多加几层阴影，而是靠几何、透视、模糊和动效服从同一个真相。

先把它当成一只环，而不是一排卡片

先把参数定下来：

  • 卡片数量 N = 22；
  • 每张卡片 180 × 300；
  • 卡片间距 gap = 18；
  • 沿弧线相邻两张卡片的步长 step = 180 + 18 = 198；
  • 环的半径 R = N × step / (2π) ≈ 693。

半径不是随手写的，而是由卡片数量和步长推出来的。这样环的周长恰好等于整排卡片的长度，首尾才能严丝合缝地接上。

x 横向展开，z 朝向观察者，卡片绕自己的竖直中轴旋转 a。bend = 1 是环内视角，环向观察者弯曲；bend = -1 是环外视角，环向远处弯曲。

切换视角时，不要直接跳变。让 bend 在 1100ms 内用 cubic-bezier(0.65, 0, 0.35, 1) 从一端过渡到另一端，整排卡片就会肉眼可见地从一个环弯成另一个环。

两个视角，是同一台摄像机的两个位置

环内和环外的差别，主要来自摄像机离正面卡片有多远。

P 是眼睛到正面卡片的距离。bend = 1 时 P = pIn，bend = -1 时 P = pOut。

  • 环内：pIn = 860px。眼睛略在环心后方，两侧卡片会靠近、变大，一屏大约看到五张：三张完整，外侧两张进入玻璃边。
  • 环外：pOut = 1500px。眼睛退到环外，以平视角度看整只环；正前方的卡片清晰，两侧和远端逐渐模糊、淡化。

如果卡片的任何部分离眼睛不到 140 个单位，或者整张卡片完全在画面外，就不画它。环内视角下，22 张卡片里通常只有五张需要参与绘制；环外才会看到整只环。

pIn = 860 不是随便挑的。它比环半径 693 略大，眼睛因此比环心再往后退约 167 个单位；这样两侧卡片仍会靠近镜头，但不会被拉得过大。pOut = 1500 则退得足够远，让环转向远处的动作显得平缓。

卡片的边、面和深度

卡片不能用普通圆角矩形。这里用的是指数为 4 的超椭圆，圆角半径 32px，对应 CSS corner-shape: superellipse(2) 的连续曲率。它的边不会在直线和圆弧的接缝处突然改变方向，所以卡片转到侧面时，轮廓仍然顺滑。

正面是四色流动渐变，背面是图片。图片要预先镜像，这样卡片翻过去之后，内容才是正的。

一个反直觉的细节：不要给卡片加阴影、反射，也不要在它转离视线时压暗。 在白色页面上，这些效果不会制造深度，只会让卡片看起来脏。深度应该来自尺寸、模糊和淡出，而不是一层灰色。

按下卡片时，它在 140ms 内缩到 0.95，松开后 320ms 恢复，缩放围绕卡片中心。这个小反馈不需要弹簧，也不需要夸张的回弹；它只是告诉用户“按到了”。

流体渐变：让颜色缓慢流动，但循环不跳

玻璃边：不是模糊，是折射

环内视角两侧的玻璃边，不是给卡片加一层高斯模糊。它是一层真正参与成像的玻璃。

做法分两遍：

  1. 先把所有卡片画进一张纹理；
  2. 再把这张纹理贴到屏幕上，并在两侧各 160px 的范围内做折射。

这个偏移沿着“指向画面中心、同时指向眼睛高度”的方向取样，所以卡片靠近玻璃时，上下边缘会向外张开，而不是像被剪刀裁掉。

0.4 × 2.4 必须小于 1。否则玻璃会把画面折回自身，出现重复的卡片或重复的间隙。这个约束不是审美偏好，而是几何上不能越过的线。

色散用七次采样模拟：红光偏得最远，蓝光偏得最少。

每个样本用一组权重混合，权重之和归一化，色边才会平滑地穿过颜色，而不是出现七条硬边。玻璃上再加一层很淡的高光，强度约为 k³ × 0.12。

玻璃边只属于环内视角。bend 靠近 0 时，它要跟着淡出；rim = 0 时完全关闭。

环外景深：逐像素，而不是 backdrop-filter

环外视角的模糊有两个来源：横向位置和前后深度。

画面中间 220px 保持清晰，越往两侧越模糊；back 从正面卡片的 0 增长到远端卡片的 1，越靠后越模糊。默认 blur = 14px。

不要用 backdrop-filter 盖在运动的卡片上。卡片在动，背景模糊会跟着闪烁；而且它只能模糊背景，不能表达“这张卡片本身离焦”。

正确做法是逐像素计算，并且给每张卡片单独算覆盖范围。一张卡片在屏幕上的左右边界分别是 dl、dr，横向覆盖率可以写成：

每张卡片绘制时，四周要留出“最大模糊半径 + 4px”的余量，否则模糊边缘会被裁掉。卡片内容也要跟着模糊：高频的噪声倍频逐渐淡出，图片从分辨率更低的 mipmap 层级读取。远端再向页面颜色淡出，默认 50%。

翻面、拖拽和惯性

从环内切到环外时，卡片会依次翻面。

整段翻面持续 1800ms，使用 cubic-bezier(0.3, 0, 0.6, 1)。每张卡片的延迟与它离正面的距离有关：

所以翻面从正前方的卡片开始，向两侧扩散。前半圈最后露出图片，后半圈仍然保持渐变；切回环内时再反向翻回去。

拖拽是一比一跟手的：指针移动多少像素，整排卡片就移动多少。松手后不立刻停住，而是带着释放速度继续滑一段：

然后吸附到最近的卡片。滑动时长按距离计算，并夹在 420–1100ms 之间，曲线用 cubic-bezier(0.25, 0.6, 0.2, 1)。按下某张卡片时，它在 760ms 内转到正前方。

还有一种“硬甩”动画，用来从环外快速打开环内：16 张卡片在 2800ms 内依次经过，曲线用 cubic-bezier(0.4, 0, 0.12, 1)。它会在很短的时间里加速，而不是瞬间跳到最高速，所以循环播放时不会在开头抖一下。

任何新动作都要停止上一个动作。减少动态效果时，关闭渐变流动，视角切换改为瞬时，滑动最多 200ms。

参数面板是设计的一部分

把关键数值做成滑块，不是为了炫技，而是为了让“手感”可以被讨论。

视角 参数 默认值 范围
环内 透视 860px 600–1400
环内 玻璃边 160px 0–240
环内 色散 25% 0–60
环内 流速 20% 0–60
环内 圆角 32px 0–60
环外 透视 1500px 900–2400
环外 景深模糊 14px 0–30
环外 远端淡出 50% 0–100
环外 流速 20% 0–60
环外 圆角 32px 0–60

滑块一动，画面立即更新，同时停止演示动画。重置按钮把所有值恢复默认。

流速的实现要注意：每帧增加的是流动角度，而不是把时间乘进噪声坐标。否则用户拖动滑块时，渐变会突然跳一大段。

实现路径

Web：用 WebGL 2 做两遍渲染。每张卡片是一排竖直的列（约 96 列，左右各多一列作为余量），在顶点着色器里放到弧线上；竖直的线在透视下仍然是直线，所以每列只需要上下两个点。图片放进一张带 mipmap 的纹理数组。先按从远到近的顺序，用预乘 alpha 把卡片画进纹理，再做玻璃遍输出到屏幕。一个 requestAnimationFrame 循环驱动全部动画。

iOS：用 Metal（MTKView）复用同样的两遍渲染；也可以用 SwiftUI 的 Metal [[stitchable]] layer effect 做玻璃遍，用 visualEffect 处理卡片。

Android：OpenGL ES 3 或 Vulkan；API 33+ 可以用 AGSL RuntimeShader 在 Compose 里画渐变和玻璃遍。

Flutter：用 FragmentProgram 做着色器，卡片用 CustomPainter 配合 drawVertices。

没有 GPU 路径时：用 CSS 3D transform 按同样的 x、z、a 摆放卡片，用 CSS 渐变代替流体；省掉玻璃遍，用几层阶梯式模糊模拟景深。效果会弱一些，但几何关系仍然成立。

检查清单

  • 环内：外侧卡片在玻璃边里平滑张开，有柔和色边，没有折叠或重复的卡片，一屏五张。
  • 环外：像一只平视的环，中间清晰，模糊向两侧和远端平滑增加，转动时没有闪烁，斜到侧面的卡片没有硬边。
  • 翻面从中间向两侧发生，图片方向正确，远端仍然显示渐变。
  • 每个滑块都能即时改变画面，数值与默认表一致，重置能恢复全部参数。
  • 拖拽一比一跟手，松手后有惯性并吸附到最近卡片，快速甩动不会跳帧。
  • 减少动态效果、浅色 / 深色页面、键盘操作参数面板都检查过。
  • 在中端手机上接近 60fps；不可见时停止渲染。

质感来自可解释的细节

这类效果最容易犯的错，是把“空间感”理解成“多加特效”：加阴影、加反光、加发光、加模糊，最后每张卡片都很漂亮，但不在同一个空间里。

真正让它成立的，是所有部分都服从同一台摄像机：卡片的弧线由曲率决定，透视由摄像机距离决定，玻璃边只折射环内视角，景深只发生在环外，翻面和拖拽都围绕同一套位置关系。关系一致之后，用户看到的才是一只环，而不是 22 张各自表演的卡片。
