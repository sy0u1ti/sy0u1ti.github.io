025 悬停延时：让悬停与切换更人性化

很多页面的悬停交互，只做了一件事：onMouseEnter 立刻弹出，onMouseLeave 立刻关掉。

鼠标刚从工具栏划过，一排 Tooltip 像放鞭炮一样噼里啪啦闪过去；好不容易等资料卡弹出来，指针刚跨过按钮和卡片之间那几像素的缝隙，卡片啪一声没了；想从列表斜着滑到右侧预览面板，半路擦到下一行，预览内容瞬间被换掉。

悬停交互显得“急躁”还是“跟手”，关键不在动画多华丽，而在用延时去识别用户意图。背后有一条非常统一的原则：

浮层越大、遮挡页面越多、内部可点内容越多，打开前等得越久，移开后留得越久；而一旦用户已经表现出“正在看”的意图，就别再让他反复等。

1. 先按体量分类，而不是按组件名分类

判断一个悬停浮层该等多久，要看它实际是什么，而不是代码里叫什么——一个塞了“关注 / 发消息”按钮的 Tooltip，本质上就是 HoverCard。

类型 典型场景 打开延时 离开宽限 组内 / 同类切换
标签（Label / Tooltip） 图标按钮说明、截断文本完整显示，无任何可点击内容 300–500ms（默认 500ms） 离开组立即隐藏，400ms 内保持热启动 组内连续移动 0ms 即时就地切换
卡片（Card / HoverCard） 人物资料卡、链接卡片、带操作按钮的浮层 700ms 150–300ms（默认 300ms）+ 缝隙透明桥接 指针慢停后就地滑动并交叉淡化
预览（Preview） 列表旁文档 / 文件预览、大图放大、导航大面板 500ms+（默认 900ms） 400ms，列表、面板与间隙同算内部 快速掠过忽略，慢停后就地换内容
不应悬停打开 主功能是操作、需要输入、需要做选择的菜单 改为点击打开 — —

最后一行经常被忽略：如果一个浮层里要打字、要填表单，或者是一组用于“做选择”而非“扫一眼”的菜单，就不要做成悬停触发，直接改为点击打开。

2. 组内“热启动”：第一次克制，后面跟手

工具栏按钮、头像组这类并排排列的触发器，最怕“路过即闪”。

  • 冷启动克制：指针首次落到某个触发器上，等待 300–500ms（默认 500ms）再弹出标签；如果在等待期间移到另一个触发器，重新计时。这样鼠标只是路过工具栏去点别的地方时，屏幕上干干净净。
  • 热启动即时：一旦首个标签弹出来了，就说明用户此刻正在浏览这一排图标。指针继续在同组内移动（包括按钮之间的空隙），应该 0ms 即时切换——标签直接移到新按钮旁边并就地换文案，不要先淡出再淡入，避免闪烁。
  • 短暂冷却期：指针离开整组触发器后，标签立即隐藏；但在此后的 400ms 内如果又回到组里，下一个标签依然 0ms 立刻显示；超过 400ms 再恢复 500ms 的等待。
  • 按下即收起：点击触发器时立刻隐藏对应标签，在指针离开该触发器之前不要再次弹出来挡视线。

3. 移入容错：给缝隙搭桥，给手抖留缓冲

只要浮层里放了链接或按钮（比如人物资料卡、下拉菜单），用户就必须把光标从触发器移进浮层里。两个地方最容易断触：

  1. 触发器与浮层之间的空隙：哪怕只有 6–8px，鼠标跨过去的一瞬间也会触发 mouseleave。解法是用一块与浮层等宽的透明桥接区盖住这条缝隙，把缝隙也算作浮层内部，跨越时绝不启动关闭计时。
  2. 边缘手抖或移速略快：指针离开触发器或浮层本体时不要立刻关闭，而是启动 150–300ms 的宽限期（大型预览面板给到 400ms）。只要在宽限期内移回触发器或浮层，就取消关闭、保持打开。
  3. 显式退出要干脆：点击页面空白处或按下 Esc，不需要等宽限期，立刻关闭。

4. 读取指针意图：别把“路过”当“想看”

对于并排的卡片、多级菜单或列表旁的预览面板，光是写死一个时间还不够，最好顺手判断一下指针的移动速度：

  • 判断快慢：记录指针最近几次坐标，计算过去 90ms 内的速度。高于约 0.1px/ms（也就是 100ms 移动超过 10px）说明在赶路；低于这个阈值，才说明在减速或停下来了。
  • 打开前防误触：进入任意触发器才启动计时，一旦切到下一项就重置，快速扫过一排元素什么都不会弹出。
  • 已打开时防误切：当一个卡片或预览已经打开，指针斜着奔向浮层时经常会擦过隔壁几行。只有当指针在新触发器上慢速停留约 60ms（停下后约 100–150ms），或者经过 150–250ms 的切换延时，才让新触发器接管内容并就地替换；快速掠过的行直接跳过。
  • 多级菜单与侧边大面板：大多数场景靠速度判断已经够用；如果斜向移动依然容易误触相邻项，就从当前指针位置到浮层近边缘拉一个安全三角区（详见本专栏 002 期《级联菜单：让子菜单不“跑丢”》）。
  • 单一时钟：所有延时共用同一套计时器管理，指针移动时及时取消，组件卸载时清理干净，并且同一类浮层同时只保留一个打开。

5. 动效、键盘、触屏与组件库配置

延时定准之后，收尾的四个细节决定它像不像成熟产品：

  • 关得总比开得快：
    • 标签：约 140ms 淡入，60ms 淡出；
    • 卡片：带 4px 下落位移约 200ms 淡入，120ms 淡出；
    • 预览：带 8px 滑入约 250ms 淡入，140ms 淡出；
    • 就地切换内容：约 200ms 交叉淡化（cross-fade），浮层打开或关闭时触发器周围的元素不能跟着抖动；
    • 开启 prefers-reduced-motion 时，去掉位移、滑动和缩放，只保留纯淡入淡出。
  • 键盘同样可达：焦点落到触发器上时，标签立刻显示并通过 aria-describedby 关联；卡片或预览在按 Enter 或经过与悬停相同的延时后打开；按 Esc 关闭并把焦点还给触发器。
  • 触屏没有悬停：在 @media (hover: none) 下，标签改成直接可见文本或长按展示，卡片和预览改为轻点打开；所有纯悬停样式放进 @media (hover: hover)，避免手机点完按钮后悬停态死死粘在屏幕上（可对照本专栏 024 期《移动端网页适配的 4 个细节》）。
  • 用库自己的参数，别在外面再套一层 setTimeout：
    • Radix UI：Tooltip.Provider 设置 delayDuration={500}、skipDelayDuration={400}；HoverCard 设置 openDelay={700}、closeDelay={300}；
    • Floating UI：标签用 useDelayGroup；卡片和预览给 useHover 配好 delay: { open, close } 并开启 handleClose: safePolygon()。

检查清单

  • 快速扫过工具栏，没有任何 Tooltip 闪出来；停在单个图标 500ms 后才出现。
  • 首个 Tooltip 出现后沿工具栏平移，标签即时就地换字，无闪动；移出超过 400ms 再回来重新等待。
  • 悬停卡片等待 700ms 打开，光标穿过缝隙去点里面的按钮不会断触；滑出边缘 300ms 内移回仍保持打开。
  • 从列表斜着滑向侧边预览面板，途经的其他行不会触发误切；真正停在另一行时原地切换内容，不先关再开。
  • 键盘焦点、Enter / Esc 和触屏点击都能触达所有原本靠悬停看到的信息。

质感来自可解释的细节

好的悬停延时平时根本不会被注意到——你不会觉得它慢，也不会被它打扰。

因为它区分了“只是路过”和“停下来看”，区分了“扫一眼小标签”和“钻进大浮层操作”。当你把冷启动、热启动、透明桥接、移出宽限和指针速度这几件事理顺之后，页面上的每一次浮现与退场都会顺着人的节奏走，而不是和光标抢拍子。
