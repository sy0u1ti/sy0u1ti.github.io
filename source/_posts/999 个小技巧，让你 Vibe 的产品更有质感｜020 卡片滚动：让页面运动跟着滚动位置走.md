不少滚动动效看起来高级，是因为页面不再只是“往下走”。

卡片会叠起来、飞出去、横向移动、旋转排开，图片也会从一个小窗口长满屏幕。用户的纵向滚动被翻译成另一种运动，于是熟悉的浏览动作突然变得有空间感。

但真正的关键不是效果有多复杂，而是每一个画面都由滚动位置直接决定：停在半路，动画就停在半路；往回滚，它原样倒放。

## 不要触发动画，要让滚动成为时间轴

普通“进入视口后播放”的动画，一旦开始就按固定时间走完。滚动只是触发器。

滚动驱动效果不同。每个 section 有一个进度 `p`：

```text
p = clamp((scrollY - start) / distance, 0, 1)
```

位移、缩放、旋转、透明度、裁切全部是 `p` 的函数，没有独立计时器。

这意味着：

- 用户滚动多快，效果就推进多快；
- 停在中间，画面保持不变；
- 反向滚动，动画严格倒放；
- 不能劫持滚轮，也不能偷偷改变滚动速度。

固定画面时，用 `position: sticky` 把内容留在视口里，再让外层 section 多出一段高度，作为动画播放距离。

## Stacked Cards：卡片自己叠成一座塔

层叠卡片适合 3–5 个并列、每个值得占一屏的内容，例如步骤、功能、方案或章节。

每张新卡从下方进入，覆盖上一张。旧卡逐渐缩小、变暗，只露出顶部约 16px 的边。

标准尺寸中，卡片约 936 × 720，圆角 28px，每张 sticky 位置比上一张低 16px。新卡到达时，旧卡按进度退缩：

```text
scale = 1 - k × 0.05
darkness = k × 0.12
```

前三张叠起后，最深的一张约缩放到 0.85。最后一卡固定后，再保留约 320px 的阅读停顿，整组才一起离开。

卡片内部只放图片、名称和一句说明。文本应该限定在网格列内，绝不能因为名字太长而跑进图片。

## Card Deck：顶部卡沿弧线飞走

卡组适合一次看一张的 3–6 个内容：精选、评价、亮点。

五张卡片先形成一叠。滚动开始后，最上面一张沿抛物线向左右交替飞出，下一张上升接替。

卡片 `i` 的飞出进度：

```text
t = clamp(scrollProgress / 420 - i, 0, 1)

x = side × t² × 1000px
y = t × (160px × t - 40px)
rot = side × t × 16deg
```

旋转原点在卡片底部中心。抛物线先略向上抬，再向下落，比单纯水平滑出更像被甩走。

后面的卡片按深度向下偏移、缩小和变暗，最多露出三层。滚动回退时，已经飞走的卡片沿同一条路径回到原位。

## Pinned Gallery：纵向滚动被翻译成横向移动

横向展廊适合 5–12 个超出屏幕宽度的项目：作品、产品、发布记录。

外层 section 的高度由横向总溢出决定，内部内容保持 sticky。页面纵向滚动多少，卡片行就向左移动多少：

```text
p = (scrollY - start) / horizontalOverflow
translateX = -p × horizontalOverflow
```

这里不能加 easing。用户滚动 1px，卡片就横移对应比例；动作与手指方向不同，但仍然完全跟手。

展廊的固定距离最好控制在约三屏以内。项目更多时，应该使用可筛选的网格，而不是让用户滚很久才看到尽头。

## Cover Flow：中间的封面最大，两侧收拢视线

Cover Flow 适合 5–9 个同形状内容：专辑、书、方案或人物。

每张封面占据一个步长。滚动进度先映射为连续的“中心索引” `c`，再计算每张卡片与中心的距离 `d`：

```text
translateX = d × 260px
rotateY = clamp(d, -1, 1) × -30deg
scale = max(0.6, 1 - |d| × 0.2)
```

中心封面最大、正面朝前；两侧封面缩小并向外旋转，越远越暗。超过 3.5 个位置后隐藏，避免在视口外堆积无意义图层。

进度在相邻封面之间使用 smoothstep，让每张封面在中心停留短暂的一刻，而不是匀速滑过。

## Image Expand：一张图片从窗口长成整个场景

图片展开适合一张足够强的图片或视频，用来开启下一段内容。

初始状态是标题与一个小图片窗口居中。滚动开始后：

- 图片窗口通过 `clip-path` 向屏幕四周打开；
- 圆角逐渐归零；
- 图片自身从 1.2 缩回 1，看起来像最终画面被“展开”出来；
- 标题更快淡出并上移。

标题、主画面、前景小字分别拥有不同缩放与位移速度，前后遮挡形成景深。主画面完全铺满后仍然固定，标题和前景字继续以不同速度上移。

下一段内容再从下方覆盖上来，顶部 28px 圆角在最后 120px 内压平，同时主画面压暗到约 35% 黑。

视频也可使用同样结构，但必须静音、循环，并只在屏幕内播放。

## 手机不是缩小版桌面

这些效果最容易在手机和短屏上坏掉。

固定区域必须使用 `100svh`，而不是 `100vh`。`100vh` 会把移动浏览器工具栏隐藏后的高度也算进去，内容因此钻到工具栏下方；`dvh` 又会随工具栏收放跳动，同样不适合固定内容。

只在加载、旋转和设备宽度变化时重新测量。高度变化小于约 120px 时忽略，那通常只是工具栏在显示或隐藏，重新计算会让卡片在滚动中突然跳位。

标准移动端策略：

| 效果 | 手机处理 |
| --- | --- |
| Stacked Cards | 保留，按视口缩放高度 |
| Card Deck | 保留，缩小卡组 |
| Pinned Gallery | 改为原生横向滚动与吸附点 |
| Cover Flow | 改为横向滑动的普通封面行 |
| Image Expand | 保留，按屏宽计算画框 |

视口高度低于 560px 时，不固定任何 section：退回列表、横向滚动行或全宽图片。

所有尺寸都需要随视口缩放。例如封面尺寸：

```text
size = min(432px, 48svh, 70vw)
```

滚动距离本身也按视口高度缩放，并遵守安全区与固定顶栏高度。

## 排版也要服从滚动结构

这些效果很容易被过多内容毁掉。

每个 section 只保留一个短标题。卡片内部保持同一结构：图片、名称、一句说明。不要加标签、侧边说明、计数器或额外 caption。

长名称必须落在自己的网格列里，不能穿过图片。卡片通常不加阴影，用背景色与图片区分即可。强调色最多出现一次。

固定 section 中的条目仍然要能通过 Tab 到达，锚点链接要落在 section 起点，键盘滚动与滚轮行为一致。

## 实现时只保留一个滚动真相

Web 端优先使用：

- `position: sticky` 做固定；
- CSS scroll-driven animations（`animation-timeline`）描述可表达为关键帧的进度；
- 对 Card Deck、Cover Flow 等需要逐卡计算的场景，用一个 passive scroll listener，每帧读取一次 `scrollY`，把进度写成 section 上的 CSS 自定义属性。

如果项目已有 GSAP ScrollTrigger 或 Motion，就沿用现有工具，不要为了一个 section 再引入第二套滚动库。

原生平台也可映射同一套进度：

- iOS：`scrollTransition` / `visualEffect`、`scrollGeometryChange`；
- Android：`LazyListState` + `graphicsLayer`；
- Flutter：`ScrollController` + `Transform` / `ClipRRect`。

无论平台，都不能平滑劫持滚动。用户的手感必须保持原样，变化的只是内容如何响应。

## 减少动态效果时先恢复内容

开启减少动态效果时，最稳妥的回退是普通 section：列表、横向行、全宽图片。

也可以保留固定，但取消位移、旋转与缩放，只留下轻微透明度变化。不要保留大幅 3D 运动却声称“减少动态”。

## 检查清单

- 每个效果是否由滚动进度直接驱动，而不是一次性触发；
- 中途停下和反向滚动是否完全可逆；
- 是否只动画 `transform`、`opacity`、`clip-path`、`filter`；
- 固定距离是否合理，没有长时间锁住页面；
- 手机是否使用 `100svh`，并处理工具栏收放；
- 短屏是否取消固定，回退为列表、横滑或全宽图片；
- 长标题是否在自己的文本列内换行；
- 固定 section 中的内容是否可通过键盘到达；
- 是否沿用了现有滚动库，没有引入滚动劫持；
- 减少动态效果、200% 文本缩放、深浅模式和真实中端手机是否都验证过。

## 质感来自可解释的细节

滚动动效真正厉害的地方，不是把页面变得复杂，而是让滚动位置成为一个可读的时间轴。

卡片往哪里走、图片什么时候打开、两侧封面如何退后，全部由用户当前的位置决定。回滚可以重来，短屏可以退回普通内容。这样滚动才有惊喜，但不会夺走控制权。
