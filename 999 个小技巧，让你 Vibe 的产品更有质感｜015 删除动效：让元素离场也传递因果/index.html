015 删除动效：让元素离场也传递因果

删除一个元素，不应该只是让它突然消失。

用户点下删除后，需要确认三件事：被删掉的确实是刚才那一项、周围内容不会跟着乱跳、空出来的位置会以可理解的方式重新排好。

原推文探索了四种卡片离场方式：燃烧、羽化、碎块和撕贴纸。它们的风格差异很大，但都遵守同一套因果：先留下证据，再处理离场，最后恢复布局。

数据先删除，画面后离场

删除动效不是延迟数据操作的加载动画。

数据应该像原来一样立即删除，界面状态也立即更新。动效只是“删除已经发生”的可视过程，不能阻塞输入，更不能等动画播完才提交。

真正需要提前完成的，是离场画面的准备：

  1. 在状态改变前读取列表项矩形；
  2. 捕获它的当前视觉快照；
  3. 隐藏真实列表项；
  4. 在列表上方播放离场效果；
  5. 同时闭合剩余项目之间的空位。

虚拟列表尤其要注意。下一次渲染后，原始节点可能已经不存在，所以截图和尺寸读取必须先于状态更新。

第一帧必须和真实项目完全一致

如果动画开始时卡片突然换了圆角、掉了一像素，或文字位置轻微移动，用户会立刻发现这是叠加的假图层。

快照要保留项目自己的背景、边框、阴影、圆角和连续曲率，并且按设备像素比至少 2 倍上传。半透明素材需要正确处理预乘 alpha，否则重新着色后会出现暗边。

对于半透明或带 backdrop-filter 的卡片，截图时还要先把它压平到真实背景上，不能只截一个透明轮廓。

离场画面可以暂时盖住邻项，但应该被列表滚动容器裁切，并位于页头、标签栏和浮动按钮之下。火焰可以从卡片位置升起，经过邻项后方，但不能盖住全局导航。

四种删除，四种材料性格

Burn：最终、戏剧性的删除

Burn 总计约 2 秒，燃烧前锋在 1.15 秒内扫过卡片。

它不是一张逐渐变黑的图，而是按顺序叠加：

  • 页面后方先出现一圈橙色火光；
  • 纸张从前锋位置经历焦黄、棕色、暖黑，再被烧穿；
  • 燃烧边界保留清晰的黑炭带和一条浅灰灰烬线；
  • 火焰从燃烧前沿向上生长，分成独立火舌；
  • 64 个火星与灰片在前锋经过后离开。

焦黑区域不能变成灰蒙蒙的烟雾。真正让燃烧可信的，是暖黑保持干净、灰烬线足够细，以及火焰的噪声只在边缘缓慢游走。

燃烧还会向未燃烧的一侧投热光。光带出现在火焰前侧，而不是把整张卡片均匀染黄；否则看起来只是换了一个暖色滤镜。

Plume：轻柔、向上的羽化

Plume 约 1.4 秒，从卡片底部升起一朵柔软火焰，把内容向上带走。

纸张底边先被拉向火焰根部，靠近燃烧线的部分变暖、上移、收窄，并轻微摆动。火焰从窄根开始，向上逐渐张开，形成分瓣、叶脉和近白色核心。

它不是把一张卡片向上擦除，而是让内容和火焰共享一个方向：底部的纸被吸入，顶端最后才烧尽。中段如果火焰最宽，就会立刻像一个色块。

Plume 适合“完成”“归档”这类正向删除。它比 Burn 轻，但仍然有明确的消散过程。

Blocks：俏皮、机械的碎裂

Blocks 约 1.5 秒，先用 70ms 的白色闪光和 4% 膨胀确认命中，再把卡片碎成三种尺寸的块。

36px 网格中：

  • 35% 保持整块；
  • 45% 拆成 18px；
  • 20% 拆成 9px。

每块保留原图的一部分，带有细描边、底边与右边的阴影，以及略微不同的亮度。所有碎块从中心爆发，速度、方向、旋转和重力共同决定轨迹。

碎块会落到可见列表底部附近，弹一次，再缩小淡出。它适合更 playful 的产品，但必须在真实列表里测试长文本、图片和滚动状态，否则碎片可能看起来像随机噪点。

Peel：可以摸到的撕贴纸

Peel 约 1.2 秒，前半段用 0.62 秒把贴纸从一角掀起。

它必须使用真实的 5px 网格，因为折起位置同时能看到正面、背面和阴影，单靠逐像素扭曲无法表现两层空间。

贴纸弯曲过程分为两段：

  • 先绕半径 20px 的圆柱弯折；
  • 离开弯折后，沿半径 420px 的宽弧继续；

两段保持弧长，所以纸张不会被拉长。折痕处有单独加深的阴影，背面使用更鲜明的同类色，并沿原卡片的圆角生成 6px 宽的白色模切边。

只有撕贴纸样式的删除，才值得承担网格、透视和两层明暗的成本。普通产品用一张贴纸效果比四套效果混用更容易成立。

邻项不是背景，它们也会感受到事件

卡片离开时，周围项目应该对正在发生的事作出反应，但只能改变 transform 和绘制，不能改变布局或阻塞输入。

Burn 和 Plume 会让最近的项目朝远离火焰的方向轻微倾斜、缩小，并在面向火焰的一侧出现局部暖光。热浪还可以用向上漂移的噪声弯曲邻项和标题，但弯曲周期要足够长，整行文字应该平滑弯曲，不能把单个字撕开。

Blocks 的碎裂冲击会让邻项短暂外推再回弹。Peel 的拉力则会把邻项向贴纸方向拉几像素，释放后再弹回。

反应强度按 1 / 距离衰减。第一邻项明显，第二邻项只剩一点，再远就应该安静。整组效果持续不足一秒时，过多邻项同时运动只会让页面失控。

空位闭合属于同一次动作

删除不是“卡片消失后，列表再换一个状态”。空位要在离场过程中开始闭合。

默认使用只作用在 transform 上的弹簧：

总时长约 520ms，但不同效果在不同时间启动：

  • Burn 在 900ms；
  • Plume 在 720ms；
  • Blocks 在 240ms；
  • Peel 在 640ms。

不要把 height、margin 或真实布局位置逐帧动画。列表项应该先有最终位置，再通过位移追赶过去。新项目如果需要补入，从下方约 60px 上移，并在前 40% 淡入；绝不能让刚被删除的文字重新出现。

弹簧不能把项目推入下一条。所有元素先按最终位置计算，再各自从旧位置出发，这与 013 中聊天线程的整体位移遵循同一原则。

真实项目需要适配尺寸和形状

原效果以约 432 × 130px 的卡片为基准。换到产品的真实列表时：

像素距离和火焰高度按 k 缩放，网格仍保持 5–6px。

明显小于 200 × 60px 的项目，应改用碎块或淡出；整行表格可以燃烧、碎裂或剥离，但羽化需要足够高度，通常要把火焰缩短并允许跨到上一行。

所有边缘计算都必须使用产品自己的圆角与曲线。使用 corner-shape: superellipse() 时，快照、模切边和火焰裁切都要遵循同一条超椭圆，不能一个用圆、一个用超椭圆。

删除必须可撤销，也必须可跳过

如果产品支持撤销，删除动画不能阻止撤回。撤销发生时，应立即终止离场效果，让原项目按产品原有方式回到列表。

最多同时允许三个离场效果。超过三个时，其他删除应退化为简短的淡出和缩小，避免多个火焰和碎块同时拖垮帧率。

在 prefers-reduced-motion: reduce 下，不播放物理效果，也不让邻项反应，只保留约 220ms 的淡出与 4% 缩小，然后闭合空位。

焦点要移动到下一个项目，读屏需要明确听到该项目已被删除。静止状态必须与修改前像素一致，没有删除时不能保留画布、shader 或循环。

平台不同，分工相同

所有实现都可以拆成四个部分：

  1. 项目快照；
  2. Burn / Plume 的逐像素 shader；
  3. Peel 的真实网格；
  4. Blocks 和粒子的大量小四边形。
平台 主要能力 回退
Web WebGL2 画布、实例化四边形、SVG 热浪滤镜 Canvas 2D 碎块或淡出
iOS SwiftUI .layerEffect、Metal 网格、Canvas Blocks 与淡出
Android AGSL RuntimeShader、Canvas mesh、OpenGL ES 淡出
Flutter Impeller FragmentProgram、Canvas Atlas 淡出
Rust wgpu 后处理与实例化渲染 淡出

Web 端还需要在删除处理器里完成截图和隐藏，再让布局库或 FLIP 处理空位。虚拟列表必须把效果画布挂在滚动容器外，否则被删除的项目会连同效果一起卸载。

先做决策，再改代码

在真实产品中接入前，需要先确认：

  • 哪些删除入口使用效果，滑动删除和批量删除默认如何回退；
  • 这一款产品只使用哪一种效果；
  • 邻项是否反应，热浪是否值得性能成本；
  • 贴纸背面取类别色还是品牌色，Plume 是否沿用原火焰配色；
  • 当前平台是否真的支持所需的快照和 shader。

然后先列出会修改的文件、列表接入点、快照方式、绘制方案、成本和回退，等待确认。删除效果不应该借机重写一个列表，也不应该引入无法维护的渲染框架。

检查清单

  • 删除数据是否立即提交，动画是否从不阻塞输入；
  • 快照是否在状态更新前完成，第一帧是否与真实项目一致；
  • 效果层是否位于滚动容器内裁切，导航是否始终在上方；
  • Burn、Plume、Blocks、Peel 是否各自符合材质与时长；
  • 邻项是否只使用 transform 与绘制，并按距离衰减；
  • 空位是否用弹簧闭合，而不是动画布局高度；
  • 尺寸、圆角、连续曲率、深色模式是否使用产品自身的 token；
  • 撤销、连续删除和降级状态是否正确；
  • 焦点、读屏、减少动态效果和静止零开销是否成立；
  • 是否先给出实现方案与平台回退，再开始修改。

质感来自可解释的细节

四种删除效果之所以不像滤镜，是因为它们共享同一条因果链：先有被删除项目的真实快照，再有符合材料特性的离场，邻项感受到事件，空位按弹簧闭合，数据没有被动画拖慢。

风格可以不同，但因果关系不能断。用户看到的不只是“卡片消失了”，而是“我删掉了这一项，周围的世界随之调整”。
