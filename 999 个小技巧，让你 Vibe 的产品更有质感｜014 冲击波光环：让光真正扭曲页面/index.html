014 冲击波光环：让光真正扭曲页面

一个真正有物理质感的光环，不应该只是罩在页面上的半透明圆。

它经过时，背后的内容会轻微变形；红蓝通道会有不同幅度的位移；页面边缘像玻璃斜边一样把内容折向内侧；连分隔线和卡片边框也会短暂捕捉到颜色。

原推文把 iOS 27.3 的屏幕边缘光感，与 Dia 打开主页时的光环冲击结合起来。它不是单纯复刻某一套视觉，而是让一次触发在页面里经过六个层。

先定义一次空间事件

光环不是永远播放的背景动画，而是一次由明确动作触发、从明确原点扩散、作用在明确区域内的事件。

触发前需要确定：

  • 点击输入框、聚焦、发送消息，还是 AI 开始回答；
  • 正在播放时再次触发，是重播、接续，还是忽略；
  • 从输入框、按钮、底部边缘、点击位置或面板中心扩散；
  • 只作用于一个面板、页面内容区，还是整个窗口；
  • 工具栏是否始终排除在外。

只要其中一项含糊，光环就会从“空间反馈”退化成随机发光。组件位置改变后，光环可能穿过工具栏、溢出圆角，甚至在用户没有操作时自行出现。

六个层，组成一次冲击

效果由六层叠加而成：

  1. 页面快照：把当前页面渲染成图像，作为后续采样的基础；
  2. 透镜扭曲：光环作为一整块透镜，把经过的页面推开；
  3. 通道分离：红色与蓝色分别以不同比例偏移，形成极轻的色散；
  4. 色环：四道宽色带平滑过渡，并随扩散淡出；
  5. 边缘折射：内容到达页面边缘时，像透过玻璃斜边一样被拉伸；
  6. 边线反光：分隔线、描边和卡片轮廓经过光环时短暂提亮。

前四层决定光环看起来像什么，后两层决定它是否真的与页面发生关系。

四道色环，先建立光的结构

光环宽度约为 110px，内部依次排列四道色带。距离光环前沿为 x 的位置，每种颜色的权重按高斯分布混合，所以相邻色环之间没有硬边。

四道环共享同一个淡出函数。光环越往外扩散，强度越低，最后全部融回页面。

浅色模式用染色：把页面颜色向色环混合，再轻微加亮。深色模式用加光：通过 screen 混合把颜色叠亮，而不是继续提高不透明度。

原效果提供四组配色：

配色 色彩方向
Aurora 蓝、紫、粉、桃
Halo 橙、琥珀、金
Frost 薄荷、青绿、浅青
Spark 紫、粉紫、金

每一组都有独立的深色与浅色版本。深色下更亮、更饱和；浅色下更柔和，避免高饱和颜色把白色页面拖脏。

透镜只弯一次，不跟着色环一起抖

最容易做错的地方，是让每个色环各自扭曲页面。那样看起来像水面涟漪，而不是有一块透明材料从空间里穿过。

正确的做法是把整个光环当成一块透镜。设距离光环前沿的归一化位置为 x，则：

页面从自身位置反向 push 的距离取样。光环外侧被拉伸，内侧被挤压，变化宽度大约与色环相同，不能扩散到整页。

颜色分离也服务于透镜，而不是彩虹效果：红色通道的位移乘 1.08，蓝色乘 0.92，绿色保持基准。偏移只出现在真正发生位移的位置，文字必须保持清晰；如果边缘出现明显彩边，就说明分离过强。

页面边缘需要保持笔直。扭曲在最后 56px 内逐渐降到零，让窗框像固定镜片的外壳，而不是也跟着融化。

到边缘时，内容像透过玻璃斜边

当光环到达页面侧边或底部，最后 60px 的区域会从更靠内的内容取样。偏移从边缘向内最多约 22px，并按二次曲线衰减：

这会让靠近边缘的文字与素材轻微向边框拉伸，窗框本身不动。光环真正碰到边缘时，再叠一条极细的高光，颜色向白色混合约 45%。

如果光环下方有工具栏，边缘折光必须避开工具栏的直线边界。效果可以覆盖内容，但不能画到浏览器或应用自己的工具条上。

让页面结构也捕捉到光

如果只有内容扭曲，而所有分隔线和描边保持原样，光环仍然像一层贴在页面上的滤镜。

可以在光环经过时，让页面里的细线一起提亮。最准确的方式是额外捕获一张只含线条的图：所有分隔线、边框和轮廓用白线画在黑底上，不包含文字、图标、图片、填充和阴影。主画面根据这张 mask 提亮，因此 1px 边框仍然只会亮 1px。

如果是 DOM retrofit，做不到整页捕获，也可以给每个带边框的元素和分隔线一个 CSS 变量，根据它们与光环前沿的距离，把 0–1 的光强写入变量，再混合边框颜色。

提亮幅度需要很克制：浅色模式约 0.3，深色模式约 0.14。文字和图标不参与这层反光；它们一旦发光，就会变成可读性问题。

节奏先快后慢，最后完全消失

默认触发是点击或聚焦 AI 输入框。光环圆心位于输入框下方约 650px，视觉上是一条从页面底部升起的宽弧。

扩散半径不是线性增长，而是前段很快、后段减速：

整段约 1000ms。强度在前 3% 快速建立，之后随 1 - t^2.2 淡出，确保到达远端时已经没有明显边缘。

如果输入框本身也参与触发，则先下压到 97% 约 90ms，再以约 580ms 的弹簧展开。光环在展开开始 40ms 后出现，金属边缘高光可以在约 900ms 内旋转一周。

这些动作共享同一个起点，但各自拥有不同职责：输入框说明“操作被接收”，光环说明“界面能量向外扩散”。

平台决定扭曲怎么实现

色环和线条反光只需要一层覆盖画面，几乎所有平台都能做。真正的难点是让页面从偏移后的位置取样。

Web

最完整的方式是用 WebGL2 或 WebGL1 覆盖画布，从页面快照里采样并一次完成色环、扭曲、分色和反光。

页面快照可以按支持情况选择：

  • HTML-in-Canvas：浏览器直接渲染页面，实时、保真，但只有部分 Chromium 版本支持；
  • foreignObject 截图库：克隆 DOM 后交给浏览器渲染，需要内联字体和图片；
  • html2canvas：重新实现 CSS，对 backdrop-filter、复杂渐变和新颜色空间容易失真；
  • 无快照回退：只画光环覆盖层，不做扭曲；Chromium 可尝试 backdrop-filter 加 SVG 位移滤镜，但成本更高。

像素比建议上限为 2，画布在静止时移除或隐藏，且必须 pointer-events: none。

平台 推荐路径 回退

不同平台的实现细节并不重要，选择标准只有两个：能否实时采样页面，以及一次快照或一次后处理的成本能否接受。

动效要能被中断，也要能被关闭

光环播放期间重新触发时，必须从当前视觉状态开始，而不是等旧动画结束再重播。主题切换时，色环随页面交叉淡化，不能先闪一下再换颜色。

在 prefers-reduced-motion: reduce 下，取消扭曲、分色和结构反光，只保留在固定位置淡入淡出的光环，亮度减半，时长约 600ms。

性能上也只应在光环可见时绘制。静止状态不应该有常驻 Canvas、持续 shader 或逐帧布局计算。

检查清单

  • 触发动作、原点、作用区域和重复触发策略是否明确；
  • 光环是否被裁剪在内容区，且从不覆盖工具栏；
  • 四道色环是否连续过渡，浅色染色与深色加光是否分开；
  • 透镜是否作为整体弯曲，而不是每个色环各弯一次；
  • 红蓝分离是否足够轻，文字是否仍然清晰；
  • 页面边缘是否保持笔直，内容是否只在边缘附近折光；
  • 线条反光是否不包含文字和图标；
  • 动效是否前快后慢，并在结束时完全消失；
  • 当前平台是否真的支持页面采样，有没有明确降级；
  • 减少动态效果和静止零开销是否都落实。

质感来自可解释的细节

冲击波光环的质感，不来自颜色更亮或扩散更大，而来自它真的经过了页面。

四道色环给出光的光谱，整体透镜说明空间的弯曲，通道分离只负责一点点透视，边缘折光与线条反光让页面结构参与进来。任何一层过量，都会从“光经过界面”变成“界面上播了一段特效”。

克制地使用物理关系，才会让一次短暂的冲击留下真实的空间记忆。
